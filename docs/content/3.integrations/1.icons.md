Code UI integrates with Iconify and `@egoist/tailwindcss-icons` at build time so you can use crisp vector icons across `<c-icon>` and component icon props with zero runtime network requests.

## Built-in Default Icons (`Lucide`)

`@code-ui/plugin-vite` ships with **Lucide (`@iconify-json/lucide`)** and `@egoist/tailwindcss-icons` built in out of the box.

Because only the icon classes actually referenced in your templates and component themes are emitted into the MiniProgram CSS bundle, including `@iconify-json/lucide` by default adds zero unused bytes to `dist/miniprogram_npm` while ensuring every component icon works immediately without extra installation.

---

## Adding Extra Icon Collections

If you want to use icons from another Iconify set alongside or instead of Lucide (such as `tabler`, `mdi`, or `heroicons`), install its `@iconify-json/{collection_name}` package:

::code-group

```bash [pnpm]
pnpm i -D @iconify-json/tabler
```

```bash [npm]
npm i -D @iconify-json/tabler
```

```bash [yarn]
yarn add -D @iconify-json/tabler
```

::

At build time, `@code-ui/plugin-vite/icons` automatically injects `@plugin "@code-ui/plugin-vite/icons";` into your app stylesheet and loads both built-in **Lucide** and any extra `@iconify-json/*` packages installed in your project.

## Configuration (`cui.config.ts`)

Customize active collections, icon utility prefix, and semantic icon aliases under `icons` in `cui.config.ts`. If `icons` is omitted, Code UI defaults to `collections: ["lucide"]`.

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  icons: {
    // Default: ["lucide"]. Add extra installed collections here:
    collections: ["lucide", "tabler"],

    // Icon utility prefix (default: "i" -> "i-lucide-check")
    prefix: "i",

    // Override built-in semantic icon aliases
    loading: "i-lucide-loader",
    check: "i-lucide-check",
    close: "i-lucide-x",
    minus: "i-lucide-minus",
    chevronDown: "i-lucide-chevron-down",
    chevronRight: "i-lucide-chevron-right",
    chevronLeft: "i-lucide-chevron-left",
    chevronUp: "i-lucide-chevron-up",
    upload: "i-lucide-upload",
    file: "i-lucide-file-text",

    // Register custom project-wide semantic icon aliases
    image: "i-lucide-image",
    video: "i-lucide-video",
    audio: "i-lucide-music",
    search: "i-lucide-search",
  },
});
```

> All icon classes from your configured `collections` presets and custom `icons` aliases in `cui.config.ts` are automatically safelisted via `@source inline(...)` by `@code-ui/plugin-vite`, so icons referenced dynamically inside components are never purged.

## Built-in Semantic Icon Aliases & Presets

Code UI components never hardcode raw icon class strings. Instead, they look up **11 built-in semantic icon aliases**. By default, these resolve to `lucide`, and if you configure another preset collection (`tabler`, `mdi`, `heroicons`) as your primary collection in `icons.collections`, Code UI automatically maps them to that collection's naming convention:

| Semantic Alias | Used By Components | `lucide` *(default)* | `tabler` | `mdi` | `heroicons` |
| --- | --- | --- | --- | --- | --- |
| `check` | `c-checkbox`, `c-select`, `c-input-menu`, `c-stepper` | `i-lucide-check` | `i-tabler-check` | `i-mdi-check` | `i-heroicons-check` |
| `minus` | `c-checkbox` *(indeterminate)* | `i-lucide-minus` | `i-tabler-minus` | `i-mdi-minus` | `i-heroicons-minus` |
| `close` | `c-modal`, `c-drawer`, `c-banner`, `c-toast`, `c-input` *(clear)* | `i-lucide-x` | `i-tabler-x` | `i-mdi-close` | `i-heroicons-x-mark` |

## Usage in Components

You can render icons standalone with `<c-icon>` or pass them to any component icon prop (`icon`, `leading-icon`, `trailing-icon`, `loading-icon`, `clear-icon`, `selected-icon`, `delete-icon`, `separator-icon`).

### 4 Supported Icon Formats

Code UI supports four formats everywhere an icon name is accepted:

1. **Tailwind Icon Class**: `"i-lucide-sparkles"`, `"i-tabler-flame"`
2. **Collection-Namespaced Shorthand**: `"tabler:sparkles"` (resolves to `"i-tabler-sparkles"`), `"heroicons:close"` (resolves via the Heroicons preset to `"i-heroicons-x-mark"`)
3. **Semantic Alias (camelCase or kebab-case)**: `"check"`, `"chevronDown"`, `"chevron-down"`, or any custom alias defined in `cui.config.ts` (e.g. `"search"`, `"image"`)
4. **Image Path / Remote URL / Data URI**: `"/assets/icons/wechat.svg"`, `"https://cdn.example.com/icon.png"` (automatically renders a native `<image>` inside `<c-icon>`)

```html [index.wxml]
<!-- 1. Standalone <c-icon> with Tailwind icon class, semantic color, or spin -->
<c-icon name="i-lucide-sparkles" size="md" color="primary" />
<c-icon name="loading" size="sm" spin />

<!-- 2. Collection-namespaced shorthand -->
<c-icon name="lucide:bell-ring" size="lg" color="warning" />

<!-- 3. Local SVG / PNG image asset -->
<c-icon name="/assets/icons/brand-mark.svg" size="xl" />

<!-- 4. Component icon props -->
<c-button
  label="Search"
  leading-icon="i-lucide-search"
  trailing-icon="i-lucide-arrow-right"
/>

<c-input
  leading-icon="i-lucide-mail"
  clearable
  clear-icon="i-lucide-circle-x"
  placeholder="you@example.com"
/>

<c-select
  items="{{options}}"
  trailing-icon="i-lucide-chevrons-up-down"
  selected-icon="i-lucide-circle-check"
/>
```

## Vite Plugin Icon Options

If you need to customize icon scaling, prefix, or extra CSS properties injected by `@code-ui/plugin-vite`, pass an `icons` options object to `codeUI()` in `weapp-vite.config.ts`:

```ts [weapp-vite.config.ts]
import { defineConfig } from "weapp-vite";
import { codeUI } from "@code-ui/plugin-vite";

export default defineConfig({
  plugins: [
    codeUI({
      icons: {
        // Automatically inject @plugin "@code-ui/plugin-vite/icons": "auto" | true | false
        autoPlugin: "auto",
        // Optional global icon scale multiplier
        scale: 1.2,
        // Optional extra CSS properties added to every generated icon rule
        extraProperties: {
          "vertical-align": "middle",
        },
      },
    }),
  ],
});
```
