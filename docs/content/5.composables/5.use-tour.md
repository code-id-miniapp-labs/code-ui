title: useTour
description: Reactive composable helper for controlling <c-tour> with zero selectComponent boilerplate, synced page state, lifecycle callbacks, and storage-backed startOnce() persistence.
---

## Overview

`useTour` wraps `<c-tour>` with an ergonomic imperative and reactive API. Instead of manually calling `this.selectComponent("#my-tour")`, syncing status flags, and managing `wx.setStorageSync` flags for one-time onboarding tours, `useTour` handles all of it in a single hook.

```ts
import { useTour } from "@code-id-labs/composables";
```

## Usage

### Binding to `<c-tour>` via `selector` (Recommended)

Pass `target: this` and `selector: "#my-tour"` to connect directly to `<c-tour>`'s live FSM via `useComponentRef`. Calling `start()` or `startOnce()` even inside `onLoad()` safely queues until `<c-tour>` finishes mounting.

::code-group

```html [index.wxml]
<c-button label="Start Tour" bind:tap="startTour" />
<c-button label="Start Once" variant="soft" bind:tap="startOnceTour" />

<view id="tour-search" class="mt-4">
  <c-input placeholder="Search..." />
</view>

<c-tour id="onboarding-tour" steps="{{ tour.steps }}" skip-label="Skip" />
```

```ts [index.ts]
import { useTour, type TourStepDetails, type UseTourReturn } from "@code-id-labs/composables";

const STEPS: TourStepDetails[] = [
  {
    id: "welcome",
    type: "dialog",
    badge: "Welcome",
    title: "Welcome to Code UI",
    description: "Let's walk through the workspace in 2 quick steps.",
  },
  {
    id: "search",
    type: "tooltip",
    target: "#tour-search",
    title: "Quick Search",
    description: "Find any item immediately from the search bar.",
    placement: "bottom",
  },
];

Page({
  data: {
    tour: {
      steps: STEPS,
      status: "idle",
      completed: false,
    },
  },

  tourCtrl: null as UseTourReturn | null,

  onLoad() {
    this.tourCtrl = useTour({
      target: this,
      selector: "#onboarding-tour",
      key: "tour",
      steps: STEPS,
      storageKey: "onboarding_v1_done",
      onComplete() {
        console.log("Onboarding finished!");
      },
      onSkip() {
        console.log("User skipped tour");
      },
    });

    // Runs once per user; skipped automatically once completed
    this.tourCtrl.startOnce();
  },

  onUnload() {
    this.tourCtrl?.stop();
  },

  startTour() {
    this.tourCtrl?.start();
  },

  startOnceTour() {
    this.tourCtrl?.startOnce();
  },
});
```

### Controlled Mode (Without `selector`)

If you prefer binding `open` and `step-id` explicitly in WXML, omit `selector` and forward events with `handleStepChange`, `handleStatusChange`, and `handleOpenChange`:

::code-group

```html [index.wxml]
<c-tour
  open="{{ tour.open }}"
  step-id="{{ tour.stepId }}"
  steps="{{ tour.steps }}"
  bind:stepChange="onTourStepChange"
  bind:statusChange="onTourStatusChange"
  bind:openChange="onTourOpenChange"
/>
```

```ts [index.ts]
import { useTour, type UseTourReturn } from "@code-id-labs/composables";

Page({
  data: {
    tour: { open: false, stepId: null, steps: [] },
  },

  tourCtrl: null as UseTourReturn | null,

  onLoad() {
    this.tourCtrl = useTour({
      target: this,
      key: "tour",
      steps: [
        { id: "step-1", type: "dialog", title: "Step 1", description: "Controlled mode." },
      ],
    });
  },

  onTourStepChange(e: WechatMiniprogram.CustomEvent) {
    this.tourCtrl?.handleStepChange(e);
  },

  onTourStatusChange(e: WechatMiniprogram.CustomEvent) {
    this.tourCtrl?.handleStatusChange(e);
  },

  onTourOpenChange(e: WechatMiniprogram.CustomEvent) {
    this.tourCtrl?.handleOpenChange(e);
  },
});
```

### One-Time Onboarding Persistence (`storageKey`)

Provide `storageKey` to automatically persist completion via `wx.setStorageSync`:

- `tour.startOnce(stepId?)` starts the tour only when `!tour.hasCompleted()`, returning `true` if launched and `false` otherwise.
- Set `markCompletedOnSkip: true` if skipping should also count as completed.
- Call `tour.resetCompleted()` to clear the flag (e.g. from a "Replay Tutorial" button in Settings).

## Options (`UseTourOptions`)

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `target` | `UseTourTarget` | `undefined` | Page or Component instance (`this`) used for `selectComponent` and/or `setData`. |
| `selector` | `string` | `undefined` | Selector pointing to `<c-tour id="..." />` (e.g. `"#main-tour"`). |
| `key` | `string` | `undefined` | Data key under `target.data` where reactive tour state and `steps` are synced. |
| `steps` | `TourStepDetails[]` | `[]` | Ordered list of tour steps. |
| `defaultStepId` | `string \| null` | `null` | Default starting step id. |
| `storageKey` | `string` | `undefined` | Storage key for persisting completion state via `wx.getStorageSync` / `wx.setStorageSync`. |
| `markCompletedOnSkip` | `boolean` | `false` | Whether calling `skip()` also marks `storageKey` as completed. |
| `getProgressText` | `(details) => string` | `undefined` | Custom progress text formatter in controlled mode. |
| `onChange` | `(snapshot: UseTourSnapshot) => void` | `undefined` | Fired whenever the tour snapshot changes. |
| `onStart` | `() => void` | `undefined` | Fired when the tour starts. |
| `onStepChange` | `(details: TourStepChangeDetails) => void` | `undefined` | Fired when the active step changes. |
| `onStatusChange` | `(details: TourStatusChangeDetails) => void` | `undefined` | Fired when tour status transitions. |
| `onOpenChange` | `(details: TourOpenChangeDetails) => void` | `undefined` | Fired when open state toggles. |
| `onComplete` | `() => void` | `undefined` | Fired when the tour completes. |
| `onSkip` | `() => void` | `undefined` | Fired when the tour is skipped. |
| `onDismiss` | `() => void` | `undefined` | Fired when the tour is dismissed. |

## Return Value (`UseTourReturn`)

| Property / Method | Description |
| :--- | :--- |
| `open`, `visible`, `status`, `step`, `stepId`, `stepIndex`, `totalSteps`, `hasNextStep`, `hasPrevStep`, `firstStep`, `lastStep`, `progressPercent`, `progressText`, `completed` | Live readonly state getters. |
| `getState()` | Returns a plain `UseTourSnapshot` copy. |
| `start(stepId?)` | Starts the tour at the default or specified step (queues safely if called before `<c-tour>` mounts). |
| `startOnce(stepId?)` | Starts the tour only if `!hasCompleted()`, returning `boolean`. |
| `setOpen(open)` | Imperatively opens or closes the tour. |
| `next()` / `prev()` / `goTo(idOrIndex)` | Step navigation commands. |
| `skip()` / `dismiss()` / `close()` | Exit commands with corresponding lifecycle statuses. |
| `reposition()` | Triggers target re-measurement on the bound `<c-tour>`. |
| `setSteps(steps)` | Dynamically replaces the tour steps list. |
| `hasCompleted()` / `markCompleted()` / `resetCompleted()` | Persistence helpers backed by `storageKey`. |
| `handleStepChange(e)` / `handleStatusChange(e)` / `handleOpenChange(e)` | WXML event bridge handlers for controlled mode. |
| `stop()` | Cleans up reactive subscriptions (call in `onUnload` / `detached`). |
