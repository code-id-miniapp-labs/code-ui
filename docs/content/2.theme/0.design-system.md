Code UI is built on a semantic design system inspired by Nuxt UI v4 and Tailwind CSS v4, tailored specifically for WeChat MiniProgram (`weapp`). Instead of hardcoding raw palette shades like `bg-zinc-100 dark:bg-zinc-800` on every element, components consume semantic tokens (`bg-elevated`, `text-highlighted`, `border-accented`, `bg-primary`) that automatically adapt between light and dark modes—even across MiniProgram custom component boundaries (`apply-shared`) and `<root-portal>` overlays.

## Semantic Colors

Code UI defines **7 built-in semantic color roles**. Every color-aware component (`c-button`, `c-badge`, `c-alert`, `c-chip`, `c-switch`, `c-checkbox`, `c-progress`, etc.) accepts these color names via its `color` prop:

| Color       | Default Palette | CSS Variable      | Role                                                     |
| ----------- | --------------- | ----------------- | -------------------------------------------------------- |
| `primary`   | `red`           | `--ui-primary`    | Primary brand actions, active indicators, and focus rings |
| `secondary` | `stone`         | `--ui-secondary`  | Secondary accents and complementary highlights           |
| `neutral`   | `zinc`          | `--ui-neutral`    | Monochrome controls, subtle surfaces, and neutral states |
| `danger`    | `red`           | `--ui-danger`     | Destructive actions, errors, and invalid form states     |
| `success`   | `green`         | `--ui-success`    | Positive confirmations, online badges, and valid states  |
| `warning`   | `amber`         | `--ui-warning`    | Cautionary notices, expiring states, and warnings        |
| `info`      | `blue`          | `--ui-info`       | Informational banners, help callouts, and tips           |

### Configuring Colors

Map any semantic role to a Tailwind color palette or a custom hex/RGB value under `ui.colors` in `cui.config.ts`:

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  ui: {
    colors: {
      primary: "emerald",
      secondary: "indigo",
      neutral: "zinc",
      danger: "rose",
      success: "green",
      warning: "amber",
      info: "sky",
    },
  },
});
```

### Supported Color Palettes

Each color in `ui.colors` can be set to:

1. **Any built-in Tailwind CSS v4 color palette** (automatically generates `50`–`950` shade variables and shifts from `500` in light mode to `400` in dark mode for optimal contrast):
   - **Neutral palettes**: `slate`, `gray`, `zinc`, `neutral`, `stone`, `mauve`, `olive`, `mist`, `taupe`
   - **Chromatic palettes**: `red`, `orange`, `amber`, `yellow`, `lime`, `green`, `emerald`, `teal`, `cyan`, `sky`, `blue`, `indigo`, `violet`, `purple`, `fuchsia`, `pink`, `rose`
2. **A custom `@theme` palette name** defined in your `app.css` / `app.wxss` (e.g. `"brand"`, which maps `--ui-color-primary-50`..`950` to `--color-brand-50`..`950`).
3. **A direct Hex or CSS color function** (e.g. `"#10b981"` or `"rgb(16, 185, 129)"`), which binds `--ui-<color>` and pre-computes alpha variables (`--ui-<color>-a5`..`a90`) directly.

#### Custom `@theme` Palette in CSS

To define your own palette in CSS (for example `brand`) and map it to `primary` in `cui.config.ts`, declare the color scale in your `app.css` / `app.wxss` using Tailwind's `@theme` block:

::code-group

```css [app.css]
@import "tailwindcss";

@theme {
  --color-brand-50: #eef2ff;
  --color-brand-100: #e0e7ff;
  --color-brand-200: #c7d2fe;
  --color-brand-300: #a5b4fc;
  --color-brand-400: #818cf8;
  --color-brand-500: #6366f1;
  --color-brand-600: #4f46e5;
  --color-brand-700: #4338ca;
  --color-brand-800: #3730a3;
  --color-brand-900: #312e81;
  --color-brand-950: #1e1b4b;
}
```

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  ui: {
    colors: {
      primary: "brand",
    },
  },
});
```

::

> [!IMPORTANT]
> Make sure **all 11 shades (`50` to `950`)** are defined when creating a custom `@theme` palette. Components reference shades across the full scale (such as `50`/`100` for soft backgrounds, `400`/`500` for solid and dark mode states, and `700`/`900` for text contrast).

### Adding Custom Semantic Colors

You can register your own custom semantic color keys (such as `brand` or `accent`) in `ui.colors`. At build time, `@code-ui/plugin-vite` passes your custom colors alongside the 7 built-in semantic colors into every component theme factory so `<c-button color="brand" />` or `<c-badge color="vip" />` works automatically:

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  ui: {
    colors: {
      primary: "stone",
      brand: "violet",
      vip: "#d97706",
    },
  },
});
```

### Semantic Color Utilities

Every configured color can be used directly in your WXML templates with standard Tailwind utilities:

| Utility Pattern | Example | Description |
| --- | --- | --- |
| `bg-<color>` | `bg-primary`, `bg-danger` | Uses `--ui-<color>` (`500` in light mode, `400` in dark mode) |
| `text-<color>` | `text-primary`, `text-success` | Uses `--ui-<color>` for text and icon color |
| `border-<color>` | `border-primary`, `border-warning` | Uses `--ui-<color>` for border color |
| `bg-<color>-<shade>` | `bg-primary-50`, `bg-primary-900` | Uses the specific shade (`50`–`950`) from `--ui-color-<color>-<shade>` |
| `bg-<color>/<alpha>` | `bg-primary/10`, `ring-primary/20` | Uses pre-computed RGBA alpha tokens (`--ui-<color>-a10`, `--ui-<color>-a20`) |

## Typography & Text Hierarchy

Code UI provides **6 semantic text color utilities** mapped to your configured `neutral` palette. They automatically invert in dark mode to preserve visual hierarchy without manual `dark:text-*` classes:

| Utility Class      | CSS Variable            | Light (`neutral`) | Dark (`neutral`) | Recommended Usage                                      |
| ------------------ | ----------------------- | ----------------- | ---------------- | ------------------------------------------------------ |
| `text-highlighted` | `--ui-text-highlighted` | `neutral-900`     | `#ffffff`        | Page titles, card headings, active tabs, key figures   |
| `text-default`     | `--ui-text`             | `neutral-700`     | `neutral-200`    | Primary body copy, list items, and input values        |
| `text-toned`       | `--ui-text-toned`       | `neutral-600`     | `neutral-300`    | Secondary labels, subheadings, and metadata            |
| `text-muted`       | `--ui-text-muted`       | `neutral-500`     | `neutral-400`    | Descriptions, helper text, captions, and timestamps    |
| `text-dimmed`      | `--ui-text-dimmed`      | `neutral-400`     | `neutral-500`    | Input placeholders, disabled labels, and subtle hints  |
| `text-inverted`    | `--ui-text-inverted`    | `#ffffff`         | `neutral-900`    | Text placed on `bg-inverted` or high-contrast surfaces |

```html [index.wxml]
<view class="p-4 bg-default rounded-lg border border-default">
  <text class="block text-base font-semibold text-highlighted">Order Summary</text>
  <text class="block text-sm text-default mt-1">2 items ready for pickup</text>
  <text class="block text-xs text-muted mt-0.5">Updated 3 minutes ago</text>
  <text class="block text-xs text-dimmed mt-2">Promo code optional</text>
</view>
```

## Surface & Background Tokens

Code UI defines **5 semantic background utilities** for layering pages, cards, inputs, popovers, and high-contrast elements:

| Utility Class | CSS Variable       | Light (`neutral`) | Dark (`neutral`) | Recommended Usage                                                |
| ------------- | ------------------ | ----------------- | ---------------- | ---------------------------------------------------------------- |
| `bg-default`  | `--ui-bg`          | `#ffffff`         | `neutral-900`    | Primary surface for cards, modals, drawers, inputs, and popovers |
| `bg-muted`    | `--ui-bg-muted`    | `neutral-50`      | `neutral-800`    | Subtle page backgrounds, table headers, and secondary Wells      |
| `bg-elevated` | `--ui-bg-elevated` | `neutral-100`     | `neutral-800`    | Elevated cards, segmented control tracks, and soft badges        |
| `bg-accented` | `--ui-bg-accented` | `neutral-200`     | `neutral-700`    | Active/pressed surface states, skeleton blocks, and chips        |
| `bg-inverted` | `--ui-bg-inverted` | `neutral-900`     | `#ffffff`        | High-contrast tooltips, dark badges, and solid neutral buttons   |

```html [index.wxml]
<view class="p-4 bg-muted min-h-screen space-y-3">
  <view class="p-4 bg-default rounded-lg border border-default">
    <text class="text-highlighted font-medium">Default Surface</text>
    <view class="mt-2 p-3 bg-elevated rounded-md">
      <text class="text-toned text-sm">Elevated nested container</text>
    </view>
  </view>
</view>
```

## Border Radius (`ui.radius`)

Configure your design system's corner radius globally via `ui.radius` in `cui.config.ts`.

### Proportional Base Radius

When you pass a single string (or `{ base: "8rpx" }`), Code UI sets `--ui-radius` and proportionally computes the entire Tailwind radius scale (`rounded-xs` through `rounded-3xl`):

| Token          | Utility       | Scale Factor | Value (when `base = "8rpx"`) |
| -------------- | ------------- | ------------ | ---------------------------- |
| `--radius-xs`  | `rounded-xs`  | `0.5 × base` | `4rpx`                       |
| `--radius-sm`  | `rounded-sm`  | `1.0 × base` | `8rpx`                       |
| `--radius-md`  | `rounded-md`  | `1.5 × base` | `12rpx`                      |
| `--radius-lg`  | `rounded-lg`  | `2.0 × base` | `16rpx`                      |
| `--radius-xl`  | `rounded-xl`  | `3.0 × base` | `24rpx`                      |
| `--radius-2xl` | `rounded-2xl` | `4.0 × base` | `32rpx`                      |
| `--radius-3xl` | `rounded-3xl` | `6.0 × base` | `48rpx`                      |
| `--radius-full`| `rounded-full`| Fixed        | `9999px`                     |

### Custom Per-Size Overrides

You can combine `base` with explicit overrides for individual radius steps, or provide an explicit map without `base`:

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  ui: {
    // Proportional base with custom overrides for md and lg
    radius: {
      base: "8rpx",
      md: "14rpx",
      lg: "20rpx",
    },
  },
});
```

## Color Mode (`ui.colorMode`)

Code UI supports three compile-time and runtime color mode strategies configured via `ui.colorMode`:

| Mode | Compile-Time & Runtime Behavior |
| --- | --- |
| `"system"` *(default)* | Compiles both light and `dark:` classes. Automatically responds to `@media (prefers-color-scheme: dark)` AND supports explicit runtime switching via `<c-app theme="light" \| "dark">` (`data-theme="dark"` / `.dark`). |
| `"light"` | Strips all `dark:` variant classes from every component theme and omits dark CSS token blocks, producing the smallest stylesheet for light-only MiniPrograms. |
| `"dark"` | Converts `dark:` utilities into unconditional classes, removes their light-mode counterparts (e.g. `bg-white dark:bg-neutral-900` compiles to `bg-neutral-900`), and emits dark design tokens as the `:root, page, :host` defaults. |

### Runtime Theme Switching with `<c-app>`

When `@code-ui/plugin-vite`'s `appWrapper` feature is enabled (default), every page is wrapped in `<c-app>`. It provides a centralized toast/dialog host and synchronizes the active theme (`light`, `dark`, or `system`) across all child components—including overlay components rendered inside WeChat's `<root-portal>` (`c-modal`, `c-drawer`, `c-popover`, `c-action-sheet`).
