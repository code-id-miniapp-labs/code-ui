At build time, `@code-ui/plugin-vite` compiles your `cui.config.ts` design tokens into CSS custom properties and injects them into your MiniProgram app stylesheet (`app.wxss` / `app.css`). Variables are scoped to `:root, page, :host` so they cascade into both page templates and isolated WeChat MiniProgram custom components (`styleIsolation: "apply-shared"`).

## Alpha / Opacity Variables (`--ui-<color>-a*`)

To guarantee consistent opacity rendering across all WeChat MiniProgram WebView engines without relying on runtime `color-mix()`, Code UI pre-computes **9 RGBA alpha steps** for every configured semantic and custom color in both light (`500` base) and dark (`400` base) modes:

| Alpha Variable         | Opacity | Utility Example                           | Light Value (for `stone-500`)  |
| ---------------------- | ------- | ----------------------------------------- | ------------------------------ |
| `--ui-<color>-a5`      | `5%`    | `bg-primary/5`                            | `rgba(120, 113, 108, 0.05)`    |
| `--ui-<color>-a10`     | `10%`   | `bg-primary/10`                           | `rgba(120, 113, 108, 0.1)`     |
| `--ui-<color>-a15`     | `15%`   | `bg-primary/15`                           | `rgba(120, 113, 108, 0.15)`    |
| `--ui-<color>-a20`     | `20%`   | `ring-primary/20`                         | `rgba(120, 113, 108, 0.2)`     |
| `--ui-<color>-a25`     | `25%`   | `outline-primary-500/25`                  | `rgba(120, 113, 108, 0.25)`    |
| `--ui-<color>-a30`     | `30%`   | `border-primary/30`                       | `rgba(120, 113, 108, 0.3)`     |
| `--ui-<color>-a70`     | `70%`   | `text-primary/70`                         | `rgba(120, 113, 108, 0.7)`     |
| `--ui-<color>-a80`     | `80%`   | `bg-primary/80`                           | `rgba(120, 113, 108, 0.8)`     |
| `--ui-<color>-a90`     | `90%`   | `bg-primary/90`                           | `rgba(120, 113, 108, 0.9)`     |

At build time, `@code-ui/plugin-vite`'s post-processor (`compatSemanticColorVariables`) automatically rewrites compiled Tailwind opacity utilities (like `.bg-primary/10` or `.ring-primary/20`) to reference `var(--ui-primary-a10)` and `var(--ui-primary-a20)` so runtime theme changes update translucent backgrounds, borders, and focus rings instantaneously.

## Border Radius Variables

When `ui.radius` is configured in `cui.config.ts`, the following radius variables are emitted onto `:root, page, :host` and `@theme default inline`:

| Variable         | Default / Computed Formula       | Tailwind Utility |
| ---------------- | -------------------------------- | ---------------- |
| `--ui-radius`    | Base radius (e.g. `8rpx`)        | —                |
| `--radius-xs`    | `calc(var(--ui-radius) * 0.5)`   | `rounded-xs`     |
| `--radius-sm`    | `var(--ui-radius)`               | `rounded-sm`     |
| `--radius-md`    | `calc(var(--ui-radius) * 1.5)`   | `rounded-md`     |
| `--radius-lg`    | `calc(var(--ui-radius) * 2)`     | `rounded-lg`     |
| `--radius-xl`    | `calc(var(--ui-radius) * 3)`     | `rounded-xl`     |
| `--radius-2xl`   | `calc(var(--ui-radius) * 4)`     | `rounded-2xl`    |
| `--radius-3xl`   | `calc(var(--ui-radius) * 6)`     | `rounded-3xl`    |
| `--radius-full`  | `9999px`                         | `rounded-full`   |

## Generated Selectors & MiniProgram Isolation

When `ui.colorMode` is `"system"` (default), `@code-ui/plugin-vite` emits four CSS blocks so variables work seamlessly across system dark mode, manual `<c-app>` theme toggling, custom component shadow roots (`:host`), and `<root-portal>` overlays:

1. **Base & Custom Component Host (`:root, page, :host`)**:
   Defines all light-mode `--ui-*` tokens plus transform reset defaults (`--tw-translate-x: 0; --tw-translate-y: 0; --tw-translate-z: 0;`) required by isolated MiniProgram components.
2. **System Dark Mode (`@media (prefers-color-scheme: dark)`)**:
   Switches `:root, page, :host` to dark tokens when the device is in dark mode.
3. **Explicit Light Override (`page[data-theme="light"], .light, [data-theme="light"]`)**:
   Forces light tokens even when the OS is in dark mode.
4. **Explicit Dark Override (`page[data-theme="dark"], .dark, [data-theme="dark"]`)**:
   Forces dark tokens when `<c-app theme="dark">` is active.

> [!NOTE]
> Components rendered inside WeChat's `<root-portal>` (`c-modal`, `c-drawer`, `c-popover`, `c-action-sheet`) escape the page's DOM subtree. Code UI's `createAppThemeBehavior` automatically forwards the active `data-theme` attribute and theme class from `<c-app>` onto the portal wrapper so CSS variables and `dark:` utilities remain in sync.

## Using & Overriding Variables in WXSS

You can consume any `--ui-*` variable directly in your custom WXSS rules, or override specific tokens on a page or container subtree:

```css [app.wxss]
/* 1. Consume semantic tokens in custom classes */
.custom-panel {
  background-color: var(--ui-bg-elevated);
  color: var(--ui-text-highlighted);
  border: 1px solid var(--ui-border-accented);
  border-radius: var(--radius-lg, 16rpx);
}

/* 2. Override semantic tokens for a specific container or theme section */
.vip-theme-section {
  --ui-primary: #d97706;
  --ui-primary-a10: rgba(217, 119, 6, 0.1);
  --ui-primary-a20: rgba(217, 119, 6, 0.2);
}
```
