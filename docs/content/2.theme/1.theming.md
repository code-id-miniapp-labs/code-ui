title: Theming

---

Code UI uses a slot-based Tailwind Variants (`tv`) architecture inspired by Nuxt UI v4. At build time, `@code-ui/plugin-vite` merges each component's theme definition with your `cui.config.ts` overrides, compiles them into compact virtual modules (`virtual:cui/theme/<component>`), and injects only the used component classes into your MiniProgram stylesheet via `@source inline(...)`.

## Global Configuration (`cui.config.ts`)

Create a `cui.config.ts` file at your project root to configure your component tag prefix, design tokens, icons, and global component overrides:

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  // Global component tag prefix (used by autoImport and <c-app> wrapper)
  prefix: "c",

  // Design tokens (colors, colorMode, radius, font, transition)
  ui: {
    colors: {
      primary: "stone",
      secondary: "amber",
      neutral: "zinc",
      danger: "red",
      success: "green",
      warning: "amber",
      info: "blue",
    },
    colorMode: "system",
    radius: {
      base: "8rpx",
    },
  },

  // Global icon collections and semantic icon overrides
  icons: {
    collections: ["lucide"],
  },

  // Component-level theme overrides (both camelCase and kebab-case keys are typed)
  components: {
    button: {
      defaultVariants: {
        size: "md",
        variant: "solid",
      },
      slots: {
        root: "rounded-full",
      },
    },
  },
});
```

### Top-Level Options

| Option       | Type                | Default | Description                                                                                                                                      |
| ------------ | ------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `prefix`     | `string`            | `"cui"` | Global prefix for custom components (e.g. `"c"` for `<c-button>` or `"cui"` for `<cui-button>`), used for WXML auto-import and `<c-app>` injection. |
| `ui`         | `UIConfig`          | `{}`    | Global design tokens (`colors`, `colorMode`, `radius`, `transition`, `font`).                                                                    |
| `icons`      | `IconsConfig`       | `{}`    | Active Iconify collections, custom prefix, and global semantic icon aliases.                                                                     |
| `components` | `ComponentRegistry` | `{}`    | Type-safe per-component theme overrides (`slots`, `variants`, `compoundVariants`, `defaultVariants`).                                            |

## Global Component Overrides

Every component in `components.<name>` is broken down into named **slots** (e.g. `root`, `base`, `label`, `leadingIcon`, `trailingIcon`, `content`), **variants** (`variant`, `size`, `color`, etc.), **compoundVariants**, and **defaultVariants**.

Both `camelCase` (`pinInput`, `inputMenu`) and `kebab-case` (`"pin-input"`, `"input-menu"`) component names are fully typed in `cui.config.ts`.

### 1. Overriding Slot Classes (`slots` / `ui`)

Pass a class string to any slot under `components.<name>.slots` (or its alias `ui`). Code UI automatically merges your classes with the component's built-in slot classes and resolves conflicting Tailwind utilities (for example, `rounded-full` automatically replaces the default `rounded-md`):

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  components: {
    button: {
      slots: {
        root: "rounded-full font-semibold",
        label: "tracking-wide",
      },
    },
    card: {
      slots: {
        root: "shadow-sm",
        header: "bg-muted/50",
      },
    },
  },
});
```

### 2. Transforming `defaultClass` with a Function

When you need full control over a slot's built-in classes—such as replacing a specific utility, filtering out a class, or conditionally transforming the defaults—pass a function `(defaultClass: string) => string` to any slot in `slots` (or inside `variants`):

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  components: {
    button: {
      slots: {
        // Append to or transform the built-in defaultClass string at compile time
        root: (defaultClass) =>
          `${defaultClass.replace("rounded-md", "rounded-full")} active:scale-95`,
      },
    },
    drawer: {
      slots: {
        // Completely replace a slot's default classes by ignoring defaultClass
        handle: (_defaultClass) => "w-16 h-1.5 rounded-full bg-primary/40 mx-auto my-2",
      },
    },
  },
});
```

> [!TIP]
> Function replacers run at build time inside `@code-ui/plugin-vite`. Any Tailwind classes returned by your `(defaultClass) => ...` function are automatically extracted and safelisted in your MiniProgram stylesheet.

### 3. Overriding & Extending `variants`

Customize existing variant options (`variant`, `size`, `color`, etc.) or register brand-new variant values for any component:

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  components: {
    button: {
      variants: {
        size: {
          // Override specific slots for an existing size
          md: {
            root: "h-10 px-5 text-sm",
          },
          // Or transform the existing variant slot classes via defaultClass
          lg: {
            root: (defaultClass) => `${defaultClass} font-bold`,
          },
        },
        variant: {
          // Add a custom variant option usable via <c-button variant="glass" />
          glass: {
            root: "bg-white/70 backdrop-blur-md border border-white/30 text-highlighted",
          },
        },
      },
    },
  },
});
```

### 4. Adding `compoundVariants`

Use `compoundVariants` to apply classes when multiple variant conditions match simultaneously (such as a specific `color` + `variant` or `size` + `square` combination):

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  components: {
    button: {
      compoundVariants: [
        {
          color: "primary",
          variant: "solid",
          class: {
            root: "shadow-md shadow-primary/25",
          },
        },
      ],
    },
  },
});
```

### 5. Changing Global `defaultVariants` (`defaultProps`)

Override the default variant values of any component globally via `defaultVariants` (or its alias `defaultProps`):

```ts [cui.config.ts]
import { defineConfig } from "@code-ui/plugin-vite";

export default defineConfig({
  components: {
    button: {
      defaultVariants: {
        size: "lg",
        variant: "soft",
        color: "primary",
      },
    },
    input: {
      defaultVariants: {
        size: "lg",
        variant: "outline",
      },
    },
  },
});
```

## Per-Instance Overrides (`ui` & `class` Props)

Every Code UI component accepts two styling props in WXML for instance-level customization:

- **`ui`** (`Object`): A map of `{ [slotName]: classString }` that overrides any internal anatomy slot for that specific component instance.
- **`class`** / **`className`** (`String`): Extra Tailwind classes applied directly to the component's root/base slot.

::code-group

```html [index.wxml]
<c-card
  title="Custom Styled Card"
  description="Per-instance slot overrides via the ui prop."
  ui="{{cardUi}}"
  class="shadow-lg"
>
  <view class="text-sm text-default">
    Card body content with custom header and footer slot styles.
  </view>
  <view slot="footer" class="flex justify-end gap-2">
    <c-button
      label="Confirm"
      ui="{{ { root: 'rounded-full px-6', label: 'tracking-wider uppercase' } }}"
    />
  </view>
</c-card>
```

```ts [index.ts]
Page({
  data: {
    cardUi: {
      root: "rounded-2xl border-primary/30",
      header: "bg-primary/5 border-b border-primary/15",
      title: "text-primary font-bold",
      body: "p-6",
      footer: "bg-muted/50 px-6 py-3",
    },
  },
});
```

::

### Smart Class Deduplication & MiniProgram Escaping

When resolving `ui` and `class` overrides at runtime, Code UI's `tv()` and `resolveSlots()` engine automatically:

1. **Deduplicates conflicting Tailwind utilities** (`dedupeClasses`): Passing `p-6` in `ui.body` cleanly removes the default `p-4` (as well as shorthand conflicts like `px-*` / `py-*`), and passing `bg-primary` removes `bg-default`.
2. **Escapes MiniProgram-unsafe characters** (`escapeClass`): Arbitrary values and modifiers like `bg-primary/10`, `min-w-[120px]`, or `data-[state=open]:opacity-100` are automatically escaped to match `weapp-tailwindcss` WXSS selectors.
3. **Memoizes default slots**: When a component instance has no `ui` or `class` overrides, `resolveSlots()` returns a `WeakMap`-cached slot map in $O(1)$ time with zero string allocations.
